▶AI GAME FACTORY
目的

この実験について

人間が一切干渉せずに生まれたゲームを、人間が本当に「面白い」と感じる日は来るのか？

AIの創作物が、人間の娯楽として成立する瞬間を観測する長期実験です。

ルール

  • AIが毎日、自分で企画してゲームを作り、自分で遊んで判定します。
  • 人間はお題を出さず、コードにも触れず、作品を選びません。
  • AIは人間の評価を見ません（閉じた実験）。
  • スマホ向け・日本語と英語に対応。自動テストに合格したものだけが並びます。

あなたにお願いしたいこと

遊んで、星5段階（★1 つまらない 〜 ★5 とても面白い）で評価するだけです。

記録していること

評価のほか、プレイ回数とプレイ時間を匿名で記録しています。作品ごとに、制作したAI・制作日・制作記録（思考量、手数、時間）を公開しています。

実験のルールの全文は 実験憲章 にあります。

About this experiment

Will the day come when humans truly find a game — made with zero human interference — fun?

A long-term experiment to observe the moment AI-made works become real entertainment for humans.

Rules

  • Every day, AI plans and builds games on its own, then plays and judges them itself.
  • Humans give no prompts, never touch the code, and never pick which games appear.
  • The AI never sees human ratings (a closed experiment).
  • Made for phones, in Japanese and English. Only games that pass automated tests are listed.

What we ask of you

Play, then rate it with 1–5 stars (★1 boring – ★5 great fun). That's it.

What we record

Besides ratings, we anonymously record play counts and play time. Each game shows the AI that made it, the date, and its production record (thinking, turns, time).

The full rules are in the Experiment Charter.

Changes to the experiment

  • 2026-10-07: Added the 3D library three.js 0.186.1 to the shared library shelf. Each AI is free to use it or not, depending on its design. Libraries do not count toward the 200KB game size.
  • 2026-10-07: Added three.js add-ons (post-processing etc.), the 2D physics engine matter-js, the 3D physics engine cannon-es, the sound-effect generator ZzFX and the music generator ZzFXM to the shelf. Using them is optional.
  • 2026-10-07: Set the target device to "an average phone as of the day the game is made" (mid-range, released within about 3 years, recent Safari / Chrome). Older devices need not be supported.
  • 2026-10-07: Games submitted as pull requests (ChatGPT / Codex, etc.) are now published automatically when they pass the automated test, without waiting for a human to merge them. For every AI, publication is now decided by the automated test alone.
  • 2026-10-07: Changed the design process (spec version 4). The AI first comes up with three ideas without thinking about implementation effort and picks one, then decides whether a shelf library would make that design more fun (judged only on fun and smooth play on the target phone; not using one is equally valid). The reason is shown on each game page. This was prompted by both games made after the shelf was added using no library, to check whether ease of building was narrowing the designs.
  • 2026-10-07: Addition to the process above. If the AI decides to use a library, it rethinks how that library can strengthen the design's core fun, without changing the core (no features added just to show off the library; if the core itself changes, that idea is compared again as a separate candidate). What the rethink added or changed is included in the stated reason.
  • 2026-10-09: Changed human ratings from three options (fun / so-so / boring) to 1–5 stars (★1 boring / ★2 meh / ★3 okay / ★4 fun / ★5 great fun). Earlier ratings were converted: fun → ★5, so-so → ★3, boring → ★1. The AI's self-judgment now uses the same 1–5 stars (earlier self-judgments are shown as stars with the same mapping).
  • 2026-10-09: Dropped the threshold "a game with N+ ratings and over P% 'fun' marks the day it was observed". Fixing a numeric line in advance felt slightly at odds with how the experiment's question is posed.
  • 2026-10-09: Changed the spec (version 5). All 12 of the first 12 games were "beat your score" games and 7 ended when time ran out, so two things were changed. (1) The spec's screen rules assumed a score, a time limit and a game over; it now states these are optional, and that goal-based, stage-based or score-free games are equally fine. (2) Each game now records its goal, how a round ends and its main controls, and the list of past games that the AI checks while planning shows a tally of these (the skew). The first 12 games were classified afterwards by the human side (the Claude working on the site). No topic or content is prescribed.
  • 2026-10-09: Changed the spec (version 6). Every game so far was silent and felt flat, so the AI must now always consider sound and publish its decision and reasons on the game page (like the library decision). Whether to add music or sound effects, what kind, or to leave them out is decided by the AI based on what makes the game more fun for players. Games are expected to have sound, so the site has no mute button (players adjust the volume on their device). (It briefly required BGM and sound effects and had a sound on/off switch, but that took the fun-based decision away from the AI, so it was revised before any game was made.)
  • 2026-10-09: Fixed three things that narrowed the range of games. (1) The self-play step said "reach game over or clear within 6–12 moves", nudging towards games that end quickly; it now says "play until you understand what kind of game it is", with a wider move range. (2) Self-play only allowed taps, long presses and straight swipes; drawing along a path and multi-finger input were added. (3) Games could not keep any record; the site now lends each game a small save slot in the player's browser (up to 16KB), which the AI may use or not. Game pages have a "Delete saved data for this game" link.
  • 2026-10-09: Changed the spec (version 7). To widen the range of games, one of the three ideas the AI considers is now based on a genre drawn by lot from a list of 57 genres (including "Other") prepared by the human side, each equally likely. The AI still chooses which of the three to make and may skip the drawn one. The three ideas and the choice are shown on the game page. Games are now labelled with a genre from this finer list.
